# Unibot

Telegram-бот с AI-генерацией — готовый шаблон для создания коммерческого бота с биллингом, подписками и админкой.

## Возможности

### AI-генерация
- **/chatgpt** — диалог с AI (GPT-5, DeepSeek V3.1 и другие модели)
- **/imagine** — генерация изображений (GPT-5 Image, Gemini 2.5 Flash, FLUX.2 Pro)
- **/edit** — редактирование изображений с AI (Gemini, GPT-5 Image)
- **/clear** — очистка контекста диалога

### Биллинг и платежи
- **3 платёжных провайдера:** YooKassa (RUB), Stripe (USD), Telegram Stars (XTR)
- **Подписки с автопродлением** (включая нативные Telegram Stars подписки)
- **Разовые покупки токенов**
- **/balance** — просмотр баланса (токены подписки + купленные отдельно)
- **кнопка в /balance** — покупка токенов или подписки

### Управление
- **SQLAdmin** — веб-админка для управления пользователями, платежами, рассылками
- **Рассылки** с сегментацией по языку, подписке, дате регистрации
- **Реферальная система** с бонусами (/invite)
- **Проверка подписки на канал** — требование подписаться перед использованием

### Дополнительно
- **Локализация** (ru/en) — /language для смены языка
- **Юридические документы** — оферта и политика конфиденциальности (/terms)
- **/settings** — настройки пользователя
- **/help** — контакт поддержки

## Быстрый старт (локальная разработка)

### 1. Создание виртуального окружения

**ВАЖНО:** Проект использует Python 3.11 (совпадает с версией на Amvera).

```bash
python3.11 -m venv .venv
source .venv/bin/activate  # Linux/macOS
# или
.venv\Scripts\activate     # Windows
```

### 2. Установка зависимостей

```bash
pip install -r requirements-dev.txt  # включает requirements.txt
```

### 3. Настройка окружения

Скопируйте `.env.example` в `.env` и укажите токен бота:

```bash
cp .env.example .env
```

Минимальные настройки для запуска:

```env
BOT__TOKEN=ваш_токен_бота
LOGGING__LEVEL=DEBUG
```

**Уровни логирования** (от самого подробного к критическому):
- `DEBUG` — всё: запросы к API, SQL-запросы, детали обработки. Для разработки.
- `INFO` — основные события: запуск, платежи, генерации. Для production.
- `WARNING` — потенциальные проблемы, которые не мешают работе.
- `ERROR` — ошибки, требующие внимания.
- `CRITICAL` — критические сбои.

Для локальной разработки рекомендуется `DEBUG`, для production — `INFO`.

### 4. Применение миграций

База данных создаётся автоматически при первом запуске миграций:

```bash
alembic upgrade head
```

### 5. Запуск бота

#### Режимы работы

Бот автоматически определяет режим работы по наличию переменной `APP__DOMAIN` в `.env`:

- **Development mode** (по умолчанию) — long polling
  - `APP__DOMAIN` не указан или закомментирован
  - Бот сам запрашивает обновления у Telegram
  - Работает на localhost

- **Production mode** — webhook
  - `APP__DOMAIN=mybot.amvera.io` указан
  - Telegram сам отправляет обновления на сервер
  - Требует HTTPS и доступность из интернета

#### Запуск в development mode

**В VSCode (рекомендуется):**

Нажмите **F5** — запустится конфигурация из `.vscode/launch.json`.

Доступно 2 режима (выбор в панели Run and Debug):
- **Unibot** — автоперезапуск при изменении `.env`
- **Unibot (Uvicorn reload)** — стандартный reload Uvicorn

**Или через командную строку:**
```bash
python scripts/run_dev.py
```

Файл `.env` отслеживается автоматически. После его изменения Uvicorn
перезапускает приложение и загружает новые переменные окружения.

#### Проверка работы

После запуска проверьте:

1. **Админка:** http://localhost:8000/admin
   Логин/пароль из `.env` (`ADMIN__USERNAME` / `ADMIN__PASSWORD`)

2. **Health check:** http://localhost:8000/health → `{"status": "ok"}`

3. **Бот:** напишите `/start` в Telegram

## Настройка AI-провайдеров

Unibot поддерживает AI-провайдеры с OpenAI-совместимым API:

### RouterAI (рекомендуется для России)

Российский сервис с доступом к GPT-5, Gemini, DeepSeek и другим моделям. Работает без VPN, оплата в рублях.

```env
AI__ROUTERAI__API_KEY=ваш_ключ
```

Получить ключ: [routerai.ru](https://routerai.ru) → Личный кабинет → API-ключи

### AnyModel (резервный провайдер)

Если `AI__ROUTERAI_API_KEY` не задан, бот использует AnyModel для моделей чата и изображений.
Добавьте ключ из раздела API Keys на [anymodel.org](https://anymodel.org):

```env
AI__ANYMODEL_API_KEY=ваш_ключ_anymodel
```

Для fallback используются модели `cx/gpt-5.6-terra` и `cx/gpt-image-2` из каталога AnyModel.

### OpenRouter (глобально)

Агрегатор 100+ моделей для международного использования.

```env
AI__OPENROUTER__API_KEY=ваш_ключ
```

Получить ключ: [openrouter.ai/keys](https://openrouter.ai/keys)

> ⚠️ Может потребоваться прокси для доступа из России

## Настройка платежей

Unibot поддерживает 3 провайдера: **Telegram Stars**, **YooKassa** (рубли), **Stripe** (доллары).

**Как это работает:** пользователь нажимает "Купить" → бот создаёт платёж → пользователь оплачивает → провайдер отправляет **webhook** → бот начисляет токены.

**Webhook** — HTTP-запрос от провайдера на ваш сервер при успешной оплате. Без него бот не узнает, что оплата прошла.

### Настройка тарифов

Тарифы настраиваются в `config.yaml`. Для каждого провайдера нужна своя цена:

```yaml
tariffs:
  starter:
    tokens: 100
    price:
      stars: 1      # Telegram Stars
      rub: 99       # YooKassa (рубли)
      usd: 0.99     # Stripe (доллары)
```

Если для провайдера не указана цена — он не будет показан как вариант оплаты.

---

### Telegram Stars (рекомендуется для старта)

Встроенная валюта Telegram. **Работает без регистрации и документов!**

**Преимущества:**
- Не нужны ИП/ООО и документы
- Пользователь платит прямо в Telegram (без редиректов)
- Поддержка подписок с автопродлением
- Webhook не нужен — Telegram сам уведомляет бота

**Курс:** ~1 Star ≈ $0.02 (устанавливается Telegram)

**Настройка:**

Telegram Stars включается в `config.yaml` (секция `payments.telegram_stars.enabled`):

```yaml
payments:
  telegram_stars:
    enabled: true
```

Готово! Telegram Stars работает сразу после включения.

---

### YooKassa (рубли, Россия)

Российская платёжная система. Принимает: карты, ЮMoney, SberPay, Tinkoff, СБП.

**Требования:** ИП или ООО (нужны документы для модерации)

#### Шаг 1: Регистрация магазина

1. Зарегистрируйтесь на [yookassa.ru](https://yookassa.ru)
2. Создайте магазин (Мои магазины → Добавить магазин)
3. Заполните данные компании и дождитесь модерации (1-3 рабочих дня)

#### Шаг 2: Получение ключей API

1. Личный кабинет → Интеграция → Ключи API
2. Нажмите "Выпустить секретный ключ"
3. Скопируйте **Shop ID** (числовой) и **Секретный ключ**

```env
PAYMENTS__YOOKASSA__SHOP_ID=123456
PAYMENTS__YOOKASSA__SECRET_KEY=live_...
```

#### Шаг 3: Настройка Webhook (ОБЯЗАТЕЛЬНО!)

Без webhook бот не узнает об успешной оплате!

1. Личный кабинет → Интеграция → HTTP-уведомления
2. Нажмите "Добавить URL для уведомлений"
3. Укажите URL: `https://ваш-домен.ru/` (просто домен со слэшем на конце)
4. Выберите события:
   - ✅ `payment.succeeded` — платёж успешен
   - ✅ `payment.waiting_for_capture` — ожидает подтверждения
   - ✅ `payment.canceled` — платёж отменён
   - ✅ `refund.succeeded` — возврат выполнен
5. Сохраните настройки

> 💡 Бот принимает webhook на корневой путь `/` — не нужно указывать `/api/webhooks/yookassa`

#### Тестирование

Для тестов создайте **тестовый магазин** (отдельно от боевого):

1. Мои магазины → Добавить магазин → Тестовый магазин
2. Shop ID будет числовым (например, `1234567`)
3. Секретный ключ начинается с `test_`

**Тестовые карты:**
| Номер карты | Результат |
|-------------|-----------|
| 5555 5555 5555 4477 | Успешный платёж |
| 5555 5555 5555 4444 | Отказ (недостаточно средств) |

Полный список: [yookassa.ru/developers/payment-acceptance/testing](https://yookassa.ru/developers/payment-acceptance/testing)

**Локальная разработка с ngrok:**

```bash
# Установите ngrok: https://ngrok.com/download
ngrok http 8000

# Скопируйте HTTPS URL (например, https://abc123.ngrok.io)
# Используйте его для webhook: https://abc123.ngrok.io/api/webhooks/yookassa
```

### Stripe (доллары, международные платежи)

Международная платёжная система. Принимает: карты, Apple Pay, Google Pay.

**Преимущества:** Работает по всему миру, быстрая регистрация.

#### Шаг 1: Регистрация

1. Зарегистрируйтесь на [stripe.com](https://stripe.com)
2. Подтвердите email и заполните данные компании
3. Дождитесь активации аккаунта

#### Шаг 2: Получение ключей API

1. Dashboard → Developers → API keys
2. Скопируйте **Secret key** (`sk_live_...` для продакшена)

```env
PAYMENTS__STRIPE__SECRET_KEY=sk_live_...
```

#### Шаг 3: Настройка Webhook

1. Dashboard → Developers → Webhooks → Add endpoint
2. URL: `https://ваш-домен.ru/api/webhooks/stripe`
3. Выберите события:
   - ✅ `payment_intent.succeeded`
   - ✅ `payment_intent.payment_failed`
4. После создания скопируйте **Signing secret** (`whsec_...`)

```env
PAYMENTS__STRIPE__WEBHOOK_SECRET=whsec_...
```

#### Тестирование

Используйте тестовые ключи (`sk_test_...`):

**Тестовые карты:**
| Номер карты | Результат |
|-------------|-----------|
| 4242 4242 4242 4242 | Успешный платёж |
| 4000 0000 0000 9995 | Отказ (недостаточно средств) |

Для тестирования webhook локально используйте [Stripe CLI](https://stripe.com/docs/stripe-cli):

```bash
stripe listen --forward-to localhost:8000/api/webhooks/stripe
```

## Деплой на Amvera Cloud

Amvera — российский PaaS с персистентным хранилищем. Данные сохраняются между деплоями.

### 1. Подготовка

1. Загрузите репозиторий на GitHub
2. Зарегистрируйтесь на [amvera.ru](https://amvera.ru)

### 2. Создание проекта в Amvera

1. Создайте новый проект
2. Выберите **"Подключить GitHub"** и авторизуйте доступ
3. Выберите репозиторий с ботом

### 3. Настройка переменных окружения

В разделе **"Переменные"** добавьте:

| Переменная | Значение | Обязательно | Описание |
|------------|----------|-------------|----------|
| `BOT__TOKEN` | `123456:ABC...` | ✅ Да | Токен от @BotFather |
| `APP__DOMAIN` | `mybot.amvera.io` | ✅ Да | Домен приложения |
| `ADMIN__USERNAME` | `admin` | Рекомендуется | Логин для админки |
| `ADMIN__PASSWORD` | `secret` | Рекомендуется | Пароль для админки |

**ВАЖНО:**
- Переменные с **двойным подчёркиванием** (`__`)
- `APP__DOMAIN` включает webhook mode (обязательно для Amvera)

### 4. Деплой

Amvera автоматически запустит сборку при подключении репозитория.

Для последующих обновлений — просто пушьте в GitHub:
```bash
git push origin main
```

Amvera сама подтянет изменения и задеплоит новую версию.

### Персистентное хранилище

Amvera автоматически монтирует `/data` как постоянное хранилище (настроено в `amvera.yml`).
Приложение само определяет, что запущено на Amvera, и сохраняет данные в `/data`.

### База данных на Amvera

По умолчанию бот использует **SQLite** — база хранится в `/data/bot.db` и сохраняется между деплоями.
Для большинства ботов это оптимальный выбор: никаких дополнительных настроек не нужно.

Если нужен PostgreSQL (например, для >10 000 активных пользователей в день):
1. Создайте базу PostgreSQL в панели Amvera
2. Добавьте переменную `DATABASE__POSTGRES_URL` в настройках приложения
3. Формат: `postgresql+asyncpg://user:pass@host:5432/dbname`

## Структура проекта

```
.
├── config.yaml              # Модели, тарифы, лимиты
├── locales/                 # Переводы (ru.yaml, en.yaml)
├── alembic/                 # Миграции БД
├── data/                    # Данные (SQLite, логи) — не в git
└── src/
    ├── app/                 # FastAPI приложение, lifecycle
    ├── api/                 # HTTP endpoints (health, webhooks)
    ├── admin/               # SQLAdmin веб-админка
    ├── bot/
    │   ├── handlers/        # Обработчики команд
    │   ├── keyboards/       # Клавиатуры
    │   └── middleware/      # Middleware (язык, cooldown)
    ├── config/              # Настройки (.env, config.yaml)
    ├── db/
    │   ├── models/          # SQLAlchemy модели
    │   └── repositories/    # CRUD операции
    ├── services/            # Бизнес-логика
    ├── providers/
    │   ├── ai/              # AI-провайдеры (OpenAI-совместимые)
    │   └── payments/        # Платежи (YooKassa, Stripe, Stars)
    ├── scheduler/           # Фоновые задачи (автопродление)
    └── utils/               # Логирование, i18n
```

### Архитектура

```
Telegram → handlers → services → providers (AI/payments)
                         ↓
                    repositories → DB
```

**Принципы:**
- Handlers только принимают запросы, бизнес-логика в services
- Repository pattern для работы с БД
- Dependency Injection для внешних зависимостей
- Все операции async/await
